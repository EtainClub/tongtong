# 지역(지방정부) 혜택 — 검토 (2026-10-06)

지금 통통의 카드·정책 항목은 모두 **중앙정부 정책**이다. 청년이 실제로 받는 혜택의 큰 몫은 지자체에 있다(서울 청년수당 같은 지역 수당, 지자체 월세·전월세 이자 지원, 면접 수당, 교통비, 지역 문화패스 등). 사용자의 지역에 맞춰 지자체 혜택을 보여 줄 수 있는지 검토한다. 이 문서는 검토와 제안이다 — 코드는 바꾸지 않았다.

## 1. 결론

**할 수 있다. 다만 지금 방식(사람이 원문과 대조한 항목·카드)으로 지자체 정책 전부를 담을 수는 없다.** 두 층으로 나누는 것을 제안한다.

| 층 | 무엇 | 검증 | 어디에 |
|---|---|---|---|
| **지역 목록** (새로) | 온통청년 공식 데이터 그대로 — 사용자 지역의 청년 정책 목록 | 통통이 검증하지 않음, 그렇게 표시 | 지역 정책 페이지, 피드 끝 화면 |
| **지역 항목·카드** (지금 방식) | 많이 찾는·큰 지역 정책을 골라 원문 대조 | 지금과 같다 | 정책 페이지·피드·청사진 |

첫 단계는 **지역을 기기에만 저장**하고, **지역 목록 화면 하나**를 여는 것이다. 서버에 지역을 남기지 않아도 된다.

## 2. 데이터 — 어디서 가져오나

| 출처 | 제공 | 확인한 것 |
|---|---|---|
| **온통청년 청년정책 API** (한국고용정보원, [공공데이터포털 15143273](https://www.data.go.kr/data/15143273/openapi.do)) | 중앙부처와 광역 17·기초 226 지자체의 청년정책 약 3,000개 | 무료, 이용허락범위 제한 없음, 실시간 갱신. **법정시군구코드로 거르는 요청 변수**가 있다. 온통청년 회원 인증키 필요([이용방법](https://www.youthcenter.go.kr/cmnFooter/openapiIntro/oaiGuide)). 응답 항목 전체(연령·신청기간·수정일 등)는 코드정의서(엑셀)에 있어 아직 확인하지 못했다 |
| 복지로 지자체 복지서비스 API (한국사회보장정보원) | 지자체 복지서비스 목록·상세(대상·선정기준·지원내용·신청방법) | 청년 전용이 아니라 생애주기로 걸러야 한다. 보조 출처 |
| 지자체별 API (예: 남해군 청년지원정책) | 일부 지자체만 | 형식이 제각각 — 쓰지 않는다 |

**온통청년 한 곳을 기본 출처로 쓴다.** 청년 정책만 모여 있고, 지역 코드로 거를 수 있고, 라이선스 제약이 없다.

확인할 것(인증키를 받은 뒤): 응답 필드(연령 범위·신청기간·최종수정일·신청 URL), 중앙정책이 지역 코드에 어떻게 들어가는지(전국 정책이 모든 지역에 반복되는지), 마감된 정책이 남는지, 호출 한도.

## 3. 지금 설계와 부딪히는 곳

1. **사실은 원문과 대조한 뒤에만 보인다** (검토 문서 4.2, README "카드 검수와 공개"). 지자체 정책 수천 개는 대조할 수 없다. → 지역 목록은 **"공식 데이터를 그대로 옮겼어요 — 통통이 확인하지 않았어요"**를 늘 붙이고, claim 칩·확정 표시를 쓰지 않는다. 금액·조건은 출처 문장 그대로, 원문 링크와 수정일을 함께.
2. **청사진의 정책은 항목에서만 온다** (청사진 설계 원칙 1). → 지역 목록의 정책은 청사진에 **넣지 못한다**. 넣으려면 항목으로 올린다(6장 R2). "찾는 정책이 없나요?"의 빈칸 요청과 같은 줄기다.
3. **자격을 판정하지 않는다** (원칙 3). → 지역 목록은 "이 지역 청년 정책"일 뿐 "받을 수 있는 정책"이 아니다. 나이 범위가 있으면 보여 주되 거르지 않는다.
4. **판단 값으로 추천하지 않는다.** → 지역은 거르는 조건일 뿐 판단과 섞지 않는다. 지금 생활 상황·관심 주제와 같은 취급.

## 4. 지역 — 어떻게 받고 어디에 두나

- **묻는 단위**: 시·도 + 시·군·구(선택). 읍·면·동은 묻지 않는다 — 혜택이 거의 시·군·구 단위이고, 더 좁으면 식별 위험이 커진다.
- **어디에 두나 (제안: 기기에만)**: 지역 목록은 브라우저가 지역 코드로 API(통통 서버가 중계)를 부르면 되므로 **서버에 사용자 지역을 저장할 필요가 없다.** `seenFacts`처럼 브라우저 저장소에 둔다. 다른 기기에서는 다시 고른다.
  - 서버에 두어야 하는 때: 지역 정책 **알림**(M7-B 알림 묶음에 "우리 지역 신청 마감")이나 기기 사이 동기화를 원할 때. 그때 프로필 필드로 옮기고 개인정보처리방침을 고친다.
- **측정**: 지역은 측정 이벤트에 싣지 않는다(지금 원칙 그대로). 시·군·구 + 나이대 + 생활 상황이 합쳐지면 작은 군에서는 사람을 좁힐 수 있다.
- **화면**: 온보딩에는 넣지 않는다(첫 화면이 길어진다). 지역 목록 화면에서 처음 열 때 고르고, 내 기록 "내 상황"에서 바꾼다.

## 5. 서버 — 중계와 캐시

- `GET /api/regional?sido=..&sigungu=..` — 서버가 온통청년 API를 인증키(Secret)로 부르고, 응답을 **필요한 필드만 남겨** 돌려준다. 지역 코드별로 하루 캐시 → 호출 한도·비용 걱정이 작다.
- 사용자 식별 정보 없이 지역 코드만 받는다(로그인·App Check는 지금 API 규칙 그대로).
- 중앙정부 정책(이미 통통에 있는 것)은 목록에서 빼거나 "통통에서 따져보기"로 잇는다 — 이름 대조 표가 필요하다.
- 대안: 매일 크론으로 전체를 받아 Firestore에 두기. 3,000건이라 가능하지만, 첫 단계는 요청 시 중계 + 캐시가 단순하다.

## 6. 단계 제안

| 단계 | 무엇 | 선결 |
|---|---|---|
| **R0** | 온통청년 인증키 발급, 응답 필드·데이터 품질 확인(서울 1개 구·작은 군 1개로 표본), 이 문서의 결정(7장) | 운영자 회원가입 |
| **R1** | 지역 고르기(기기 저장) + `/regional` 지역 목록 화면(이름·한 줄·신청기간·원문 링크·수정일, "통통이 확인하지 않았어요") + 서버 중계·캐시. 피드 끝 화면·주제 화면에 "우리 지역 청년 정책 N개" 진입 | R0 |
| **R2** | 정책 항목에 `regions`(시·도/시·군·구 코드) 필드. 많이 열린·큰 지역 정책부터 원문 대조해 항목으로 올림(예: 서울 청년수당, 각 시·도 대표 1–2개). 피드·청사진은 사용자 지역과 맞는 지역 항목만 | R1의 열람 수(측정은 정책 id 단위 합계만) |
| **R3** | 지역 항목의 카드(따져보기), 청사진 점검 "지역이 바뀌면 받을 수 없을 수 있어요", 지역 정책 알림(지역을 서버에 둘지 결정 뒤) | R2 |

R1은 코드 양이 작다(화면 1개, API 1개, 지역 선택 1개). R2부터는 콘텐츠 일이 크다 — 지금 항목 하나에 원문 대조가 든다.

## 7. 정해야 할 것

| 항목 | 선택지 | 제안 |
|---|---|---|
| 확인하지 않은 공식 데이터를 보여 줄까 | 보여 줌(표시와 함께) / 원문 대조한 것만 | **보여 줌** — 표시를 늘 붙이고 청사진·카드에는 넣지 않는다. 대조한 것만 보여 주면 지역 혜택은 몇 년 동안 비어 있다 |
| 지역을 어디에 둘까 | 기기만 / 서버 프로필 | **기기만** (R1). 지역 알림을 열 때 다시 정한다 |
| 지역 단위 | 시·도 / 시·군·구 / 읍·면·동 | **시·도 + 시·군·구(선택)** |
| 출처 | 온통청년 / 복지로 / 둘 다 | **온통청년** (청년 정책·지역 코드·라이선스). 복지로는 보조 |
| 청소년 | 지역 목록 열기 / 청년만 | 온통청년은 청년 정책이라 **청년만**으로 시작 |

**결정 (2026-10-06)**
- 확인하지 않은 공식 데이터 — **보여 준다**, "통통이 확인하지 않았어요" 표시와 함께. 청사진·카드에는 넣지 않는다.
- 지역 — **기기와 서버 둘 다**에 둔다. 서버에는 프로필 필드(`region: { sido, sigungu? }`, 선택)로 — 기기를 바꿔도 이어지고, 지역 알림(R3)의 바탕이 된다. 그래서 R1에서 함께 바꿀 것: 프로필 쓰기 규칙(`nextProfile`)·검증, 계정 삭제·내려받기에 포함(프로필에 있으므로 자동), 개인정보처리방침에 "거주 지역(시·도, 시·군·구) — 지역 정책을 보여 주고, 알림을 켜면 지역 알림에 쓴다. 측정·AI에는 쓰지 않는다". 4장의 "기기에만" 제안은 이 결정으로 바뀐다.
- 인증키 — 서비스에 **하나**. 서버만 쓴다(Secret `YOUTHCENTER_API_KEY`, 로컬 `.env.local`). 지역별로 하루 한 번 받아 캐시하므로 하루 호출은 많아야 지역 수만큼.

**R1 진행 (2026-10-06) — 지역 고르기·저장 구현, 인증키 대기**
- 지역 목록 `src/content/regions.ts` — 행정안전부 2026.7.1. 시행 법정동코드(jscode20260701)에서 만들었다. 시·도 16, 시·군·구 229. 전남광주통합특별시(12) 신설과 인천 제물포구·영종구·서해구·검단구를 반영했다. 출장소와 시 안의 일반구(수원시 장안구 등)는 고르는 단위가 아니라 뺐다. 행정구역이 바뀌면 다시 만든다.
- 프로필 `region: { sido, sigungu? }` — 목록에 없는 코드·시·도와 맞지 않는 시·군·구·사라진 코드(옛 광주 29)·일반구는 거절(`unknown-region`), 생략하면 유지, `null`이면 문서에서도 지운다(merge 저장이라 `FieldValue.delete`). 청소년은 두지 않는다. 테스트 3개 + 에뮬레이터 1개.
- 기기 사본 `tongtong:region`(`lib/region.ts`) — 서버가 기준, 기기는 사본. 다른 기기에서 지우면 이 기기에서도 지운다.
- 화면: 내 기록 "내 상황" 아래 "사는 지역" — 시·도(필수)·시·군·구(선택), 지우기. 개인정보처리방침 표에 한 줄.
- 확인할 것: 온통청년 API가 새 코드(전남광주 12xxx, 인천 새 구)를 쓰는지 옛 코드(광주 29xxx·전남 46xxx)를 쓰는지 — 인증키를 받으면 표본으로 본다. 옛 코드면 중계에서 바꿔 묻는다.
- 남은 것(키를 받은 뒤): 서버 중계·하루 캐시, "우리 지역 청년 정책" 목록 화면, 피드 끝 화면 진입 → 아래 "R1 완료".

**R0 결과 (2026-10-07) — 인증키로 실제 데이터 확인**
- 인증키: `.env.local`과 운영 Secret Manager(`YOUTHCENTER_API_KEY`, 백엔드 접근 권한 부여), `apphosting.yaml`에 RUNTIME 변수.
- 요청: `GET https://www.youthcenter.go.kr/go/ythip/getPlcy?apiKeyNm=..&pageNum=..&pageSize=..&rtnType=json&zipCd={시군구 5자리}` → `result.pagging.totCount`, `result.youthPolicyList[]`.
- **새 코드를 쓴다**: 전남광주 12xxx, 인천 28125·28155·28275·28290가 `zipCd`에 있다 — 우리 목록과 같다.
- **시 안의 일반구 코드를 쓴다**(41111 수원시 장안구 등). 우리는 "수원시"(41110)로 고르므로 중계에서 그 시의 일반구 코드로 바꿔 묻는다 — 일반구 목록을 regions에 함께 둔다.
- **지역으로 물으면 전국 정책이 함께 온다**: 마포구로 물으면 714건 중 665건이 여러 시·도에 걸친 전국 정책(고용노동부·국토교통부 등). 지역 정책 = **`zipCd`가 모두 내 시·도 안에 있는 것**. 그 가운데 코드가 하나뿐이면 "이 시·군·구만", 여럿이면 "시·도 전체".
  - 서울 마포구 49(모두 서울시 정책, 마포구만의 정책 0), 경남 남해군 95(경남 93·남해 2), 전남광주 광산구 213(광산구만 12).
  - 데이터가 섞인 곳이 있다: 서울 목록에 목포시 정책 1건 — 등록기관(`rgtrInstCdNm`)과 시·도가 맞지 않으면 빼는 것도 함께 쓴다.
- 쓸 필드: `plcyNm`, `plcyExplnCn`(한 줄), `plcySprtCn`(지원 내용), `lclsfNm`/`mclsfNm`(분야), `sprtTrgtMinAge`·`sprtTrgtMaxAge`·`sprtTrgtAgeLmtYn`, `aplyYmd`("YYYYMMDD ~ YYYYMMDD"), `aplyPrdSeCd`(0057001 기간 있음 / 0057002 상시 / 0057003 마감으로 보임 — 확인), `bizPrdBgngYmd`·`bizPrdEndYmd`·`bizPrdEtcCn`, `aplyUrlAddr`·`refUrlAddr1`, `sprvsnInstCdNm`, `lastMdfcnDt`. 소득·학력·전공 코드는 쓰지 않는다(판정하지 않는다).
- 신선도: 최근 수정 2026-10 — 살아 있다. 지난 해 신청기간이 남은 정책도 있어 "신청 마감"·기간을 날짜로 보여 준다.
- 크기: 지역 하나에 700–900건(전국 포함) → 중계는 전국 정책을 빼고 지역 정책(수십–수백 건)만 돌려준다. 시·도별 하루 캐시면 호출이 적다.

**R1 완료 (2026-10-07) — 중계·목록 화면**
- 정리 규칙 `src/lib/regional.ts`(순수 함수, 테스트 10개): 물을 코드(`queryCodes` — 시는 일반구로, 시·도만 고르면 그 첫 시·군·구로, 세종은 36110), 지역 정책 가르기(`classify`), 분야를 다섯 큰 분야로(`mainCategory`), 신청기간·상시·나이 정리(`normalize`). 나이 1세·99세·100세는 "제한 없음" 자리 채움 값이라 적혀 있지 않은 것으로 본다.
- 중계 `src/lib/server/youthcenter.ts` + `POST /api/regional`(본인 확인, 코드 검증): 지역별 하루 메모리 캐시, 실패는 캐시하지 않는다. **쪽을 나눠 한꺼번에 부르면 온통청년이 거절한다** → `pageSize=1000` 한 번, 일반구는 차례로, 실패하면 1.5초 뒤 한 번 더. 키가 없으면 503 `regional-unavailable`, 원 서버 오류는 502 `regional-upstream`.
- 화면 `/regional`(청년만): "통통이 원문과 확인하지 않았어요" 안내, 큰 분야 고르기, 신청 중 / 상시 / 신청 예정 / 기간 모름, 마감은 접어 둔다. 줄마다 원문 링크·범위(시·도 전체 / 이 시·군·구)·기관·신청기간·공고상 나이·수정일. 판정 문구 없음, 청사진·카드에 놓을 수 없다.
- 진입: 내 기록 "사는 지역" 아래 링크, 피드 끝 화면 "우리 지역 청년 정책 →"(청년).
- 확인(에뮬레이터·3100): 경기도 수원시(일반구 4개), 전남광주 광산구(이 구 8 · 시·도 전체 111), 가로 넘침 없음.
- 운영: 비밀값은 이미 넣었다 — 배포만 하면 된다. **배포 (2026-10-08)**.

**R2 선결 측정 (2026-10-08)** — R2에서 어떤 지역 정책부터 항목으로 올릴지 정한다.
- `regional_open`(목록 열람, 필드 없음) → `metrics/{날짜}.regionalOpen`. `regional_policy_open`(원문 열기, 온통청년 정책 번호 20자리만) → `metricsRegional/{날짜}.policies.{번호}`. 지역·사용자는 싣지 않는다.
- 정책 번호는 정해진 목록이 없어 모양만 검사한다 — 아무 번호나 쌓여도 하루 지표 문서가 커지지 않게 컬렉션을 나눴다.
- `pnpm metrics`에 "우리 지역 청년 정책" 표: 목록 열람 수와 원문 많이 연 정책 20개. 이름·등록 기관은 온통청년에서 번호로 하나씩 찾는다(`youthcenterPolicy`, 키는 환경 변수 또는 `.env.local`).
- 개인정보처리방침의 "자동으로 남는 것"에 한 줄.

## 8. 하지 않는 것

자격 판정("받을 수 있어요"), 지역별 혜택 합계·순위("우리 동네가 혜택이 더 많다"), 확인하지 않은 지역 정책을 피드 카드나 청사진 칸으로 넣기, 읍·면·동 수집, 지역을 측정·AI 프롬프트에 싣기.
